# 文献整理层

## 用途与权限

`literature/` 与 `raw/`、`wiki/`、`context/` 并列，面向用户的阅读、领域调研和项目思考。一页可讨论多篇论文，目录、语言、章节自由；不强制 frontmatter、英文文件名或 graph-excluded。它不是项目状态记录，也不是新的外部证据。

Agent 默认可读、检索、讨论并在对话中建议修改。创建、改写或追加整理页必须得到针对该目录或具体文件的明确授权。“摄入这篇论文”“更新 Wiki”“修复索引”均不自动授予修改整理页的权限。

## 创建与日常使用

新建库时复制 `assets/literature/` 到知识库根目录；已有目录先检查，不覆盖。四个模板只是起点，用户可以完全不用：

- `field-review.md`：方向、分类、研究问题和空白。
- `literature-comparison.md`：多篇文献的比较维度和证据。
- `reading-note.md`：单篇阅读、摘录、个人理解与疑问。
- `research-summary.md`：阶段总结及下一步阅读。

例如用户说“在 literature/交互研究/ 下建立一份多篇论文比较笔记”，才授权创建该范围。用户说“根据我的整理笔记回答”，仅授权读取。

链接原始文件到 `raw/`，全文到 `wiki/derived/`，核验记录到 `wiki/sources/`。优先相对 Markdown 链接；不要复制维护第二套全文。摘录在附近标来源及页码、章节或图表编号。原文陈述、个人判断和 Agent 分析分别标明。

本地 qmd 默认搜索 literature，排除其根 README 和 templates；安全查询降级仍保持相同范围。MCP 路线可远程检索该层；现有 AI Search 路线模板尚未接入该层，不能因为本地可查就声称远程可查。

## 仅显式请求时摄入 Wiki

1. 确认指定整理页与 Wiki 目标；只读整理页。
2. 将外部文献陈述、用户判断、Agent 分析、跨来源综合分别识别。
3. 沿引用追溯原件或官方页面，优先复用已有 source identity。缺失证据保留待核验；需要新摄入 PDF 时遵守确认、派生和 QC 流程。
4. 多来源综合进入 synthesis，定义补充进入已有 concept/entity；先查 slug 和 aliases。用户个人观点明确标注个人认知。
5. 每条知识性结论链接实际 source，整理页只作为组织依据。不为笔记、复制摘要或译文创建独立 source、raw SHA 或增加 source_count/confidence。
6. 保留指向整理页的相对链接，在 wiki/log.md 记录实际提升和来源路径。保存笔记、查询、索引刷新和日记更新本身不触发摄入。

日记记录真实完成的整理工作；项目阶段确有变化时，精炼到 persona 项目时间线并指向日记。这不授权修改 literature 或提升知识。
