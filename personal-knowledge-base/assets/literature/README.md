# 文献整理层

`literature/` 保存主要由人维护的文献调研内容，按领域、项目或研究问题组织。它与 raw、wiki、context 并列，底层文件仍放在现有位置。

## 组织与内容

按实际需要建立目录和若干 Markdown 总结页。一页可以组织多篇文献，包含方向描述、分类框架、文献关系、比较表、阅读笔记、个人理解、疑问和阶段总结。不要求 frontmatter、固定章节或英文文件名。

目录示意（尚未创建真实调研内容）：

```text
literature/
├── README.md
├── templates/
├── 某领域调研/
│   ├── 总览.md
│   ├── 方向一.md
│   └── 文献比较.md
└── 某项目调研/
    ├── 问题与文献关系.md
    └── 阶段总结.md
```

可选模板：[方向综述](templates/field-review.md)、[文献比较](templates/literature-comparison.md)、[单篇阅读笔记](templates/reading-note.md)、[阶段总结](templates/research-summary.md)。仅复制所需部分，删除不适用的提示即可，不必凑齐章节。

## 来源与阅读入口

摘要和原文片段可以直接复制到整理页，在附近注明对应来源。摘录尽量标明页码、章节或表图编号；个人理解和 Agent 分析要与原文陈述区分。

原始文件链接到 `../raw/`，完整转录和全文翻译链接到 `../wiki/derived/`，来源记录链接到 `../wiki/sources/`。上述路径相对于本 README；在子目录写笔记时，按实际深度调整相对路径。路径含空格时可写成 `[原文](<相对路径>)`。模板中的空链接需要替换为真实路径。

全文译文保留一份可校验的权威正文，供人和 Agent 阅读；本层提供链接，不另外维护一份完整副本。同一文献可在不同项目中引用，各项目保留自己的用途判断。尚未摄入的文献允许先链接 raw 原件或官方页面，但不能据此视为已核验来源。

## 编辑与摄入权限

- 用户是主要整理者。Agent 可以读取、检索、讨论，并在对话中提出建议。
- Agent 只有得到用户对文献整理层或具体文件的明确编辑授权后，才可以在授权范围内创建、改写或追加。摄入或更新 Wiki 的授权不等于修改本层的授权。
- 本层默认参与本地检索。查询、保存文件、更新索引或维护 Context 不自动触发 Wiki 更新。
- 用户明确要求将指定整理内容摄入或沉淀到 Wiki 时，Agent 才只读这些整理页，追溯实际来源、区分个人判断与外部证据，再按现有摄入和 QC 规则更新适用的知识页。未核验内容保持为线索或待核验事项。
- 整理页、笔记、复制的摘要和译文都不是新的独立外部来源，不增加 `source_count` 或 confidence。详细文献 metadata 在 Wiki 来源页维护，不要求整理页填写。

操作示例：`根据文献整理层比较这两个方向`（只读）；`允许你修改 literature/某领域调研/方向一.md，补充我指定的内容`（授权编辑）；`将 literature/某领域调研/方向一.md 中这部分结论摄入 Wiki，不修改原整理页`（仅授权 Wiki 更新）。

## 检索与实现范围

日常查询默认包含本层，也可使用 `scripts/qmd-query.ps1 -Collection literature` 单独查询。新增或修改内容后，按需运行现有 `scripts/qmd.ps1 update` 和 `embed` 更新本地检索索引；索引维护不改写整理内容。

本 README 和 `templates/**` 不进入内容检索。Wiki lint 不扫描本层，也不强制给整理页添加 frontmatter 或图谱字段。

远程范围由接入路线决定：GitHub 只读 MCP 模板支持本层，原有 GPT Actions + AI Search 模板尚未接入。本地可检索不代表远程已部署；飞书等发布渠道另行授权与配置。

详细的 Agent 约束与 metadata 获取规范见 [AGENTS.md](../AGENTS.md)。
