# 场景 1 图片提示词合同

本指南只负责把已确认的逐页文字、位置和风格参考编译成图片生成 prompt。它不生成大纲、不扩写内容、不重新设计版式，也不替用户选择内置图库条目。

## 0. 固定顺序

```text
锁定逐页完整文字与大致位置
→ 确认全量无风格版式预览
→ 展示并确认内置/用户风格参考
→ 为代表页生成 A/B/C 风格图片
→ 用户选择风格
→ 复用选中代表页
→ 只生成剩余页面
```

不得在文字和位置未确认时提前出图，也不得把风格探索推迟到正式批量生成阶段。

## 1. 已锁定的页面输入

### 1.1 完整文字

每个页面必须提供全部最终可见文字，包括标题、正文、数字、单位、标签、图表文字、注释和标点。每个文字块单独登记 `block_id`，prompt 中逐字复制，不做摘要、润色或扩写。

### 1.2 大致位置

每个文字块必须提供同一画布上的 `[x,y,w,h]` fraction bbox，并标明阅读顺序、层级和对齐方式。bbox 表达允许的落位区域，不要求像素级排版，但生成结果不得交换模块、跨区摆放或改变阅读顺序。

### 1.3 版式边界

同时写明内容区、资产预留区、装饰安全区和禁止侵入区。风格变化只能发生在既有区域内；空间不足必须回到 `slide_plan.json` 和版式预览重新确认，不能缩小文字、删减内容或挤压模块。

### 1.4 可变化的风格属性

只有下列属性可随风格方向变化：

- 配色与明暗关系；
- 字体气质和字重层级，但不改变文字内容；
- 图形、线条、材质、纹理和装饰语言；
- 留白感、边角、阴影和视觉节奏；
- 已预留资产区域内的图像表达。

不得改变页数、文字、模块数量、信息密度、bbox、阅读顺序或核心关系。

## 2. 风格选择阶段

### 2.1 生成三种方向

读取已确认 `style_reference_plan.json` 后提出 A/B/C 三个适合当前任务的落地方向。三者应有清晰差异，但必须共同来自 `selected_ids`；不得自动引入未展示、未确认的第四种视觉语言。

设最终页数为 `N`、代表页数为 `R=min(N,3)`。对同一组代表页分别生成三套图片：

- A：`style-option-a`
- B：`style-option-b`
- C：`style-option-c`

三套候选必须使用相同的完整文字、bbox、模块和阅读顺序，只比较风格。候选图片在这一阶段生成并接受视觉检查；它们不是正式生成阶段的试验品。

### 2.2 风格候选 Prompt 模板

```text
任务阶段：风格选择
页面 ID：<Pxx>
候选方向：<A|B|C>
已确认参考：<style_reference_ids>
参考使用方式：<direct|blend|inspired|custom>
画布比例：<ratio>

【已确认版式】
- 页面角色：<cover|regular|complex>
- 内容区与装饰安全区：<regions>
- 禁止改变页数、模块、阅读顺序和区域边界

【逐字文字与位置】
- <block_id> | bbox=[x,y,w,h] | order=<n> | align=<...>
  原文：<verbatim text>
- ...

【本候选风格】
- 配色：<明确颜色关系>
- 字体气质：<明确描述>
- 图形与材质：<明确描述>
- 留白与装饰：<明确描述>

【硬约束】
- 所有文字逐字准确，不生成占位符或额外文字
- 只在既有 bbox 和装饰安全区内设计
- 不增加、删除、合并或拆分内容模块
```

每次调用在 `manifests/gorden-generation.json` 记录完整 prompt、purpose、`workflow_phase: style-selection`、页面、当前 slide contract 哈希、`style_reference_ids`、模型、输出路径和哈希。

### 2.3 选择与复用

将 A/B/C 各自合成为 `R` 页图片型 PPTX，真实渲染并逐页查看。用户通过 `style-choice` 选择一个方向，并明确代表页角色到实际页面 ID 的映射。

选中方向的代表页 PNG 直接进入最终稿，不重新生成；未选中的候选只作为风格选择证据，不进入正式 `asset_plan.json`。

## 3. 正式生成阶段

正式生成阶段不再探索风格，只执行已选风格：

1. 从页清单中排除选中代表页；
2. 为其余 `N-R` 页编译 prompt；
3. purpose 使用 `final-page`；
4. `workflow_phase` 使用 `formal-generation`，并绑定当前 slide contract 哈希；
5. 使用该页锁定文字与 bbox；
6. 复用选中风格的配色、字体气质、图形语言、材质和装饰规则；
7. 只生成剩余页面，不重新生成代表页。

### 正式页面 Prompt 模板

```text
任务阶段：正式生成
页面 ID：<Pxx>
已选风格：<style-choice 中的完整风格合同>
已确认参考：<style_reference_ids>
风格参考：<选中代表页路径或生成上下文>
画布比例：<ratio>

【逐字文字与位置】
- <block_id> | bbox=[x,y,w,h] | order=<n> | align=<...>
  原文：<verbatim text>
- ...

【资产与边界】
- 资产预留区：<regions>
- 装饰安全区：<regions>
- 禁止侵入区：<regions>

【硬约束】
- 完全继承已选风格，不再提出其他风格
- 所有文字逐字准确，不生成占位符或额外文字
- 不增删模块，不改变信息密度、bbox 或阅读顺序
```

## 4. 逐页 QA

每张生成图都检查：

1. 所有已锁定文字是否存在且逐字准确；
2. 是否出现额外文字、占位符、乱码或虚构数据；
3. 每个文字块是否落在对应 bbox 的合理范围；
4. 阅读顺序、模块关系和资产预留是否保持；
5. 是否侵入装饰安全区之外的内容区；
6. 正式页面是否与选中代表页保持同一风格；
7. 选中代表页是否直接复用而没有再次生成。

任一项失败只重生成对应图片。禁止用代码补字或局部重画。

## 5. 输出与证据

- 风格候选：`work/gorden/image-deck/style-options/<a|b|c>/`
- 正式剩余页：`work/gorden/image-deck/final-pages/`
- 统一生成清单：`manifests/gorden-generation.json`
- 最终逐页图：按 `slide_plan.json` 页序汇总到交付目录
- 图片型 PPTX：每页只放对应的一张全幅 PNG

生成源图与复制后的交付图都保留。场景 1 最终必须完成全量渲染、逐页检查、对象回读和 `image-deck-final` 用户确认。
