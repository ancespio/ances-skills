# 证据、资产与字体

## 外部证据

场景 1/4 默认允许搜索。先记录候选来源、支持的主张、时间和可信度；只有 `evidence-inclusion` 确认范围内的条目可标记 `included: true` 并进入页面。

## 资产计划

每个资产记录 ID、页面、用途、类型、来源/生成方式、裁切、可编辑性和审批状态。批量生成前确认完整计划；新增计划外资产时重新确认。

场景 1 的最终页图必须以 `asset_type: png` 登记为覆盖全画布、包含语义文字且不可编辑的资产，并逐页绑定 `slide_plan.json`。A/B/C 中未入选的风格候选只保留在生成 manifest 与风格证据中，不进入最终资产计划。场景 3 的 `asset_type` 只能为 `svg` 或 `png`；PNG 必须逐项记录 bbox、视觉角色、来源类型、选择原因、编辑损失、像素尺寸和文字清理状态，并额外通过 `reconstruction-png-assets` 确认门。其他场景允许经确认的 `svg`、`raster` 或原生 PowerPoint 对象。

内置风格库的预览、参考图和 reference deck 是选择证据，不是默认最终资产。它们先进入 `style_reference_plan.json`；只有用户确认后实际复制、改编或生成进正式页面的图片、SVG、艺术字才进入 `asset_plan.json`。不得把参考稿中的照片、品牌、数据或正文因“已经打包在 Skill 中”而视为可直接使用。

## 字体

先审计所有指定或模板字体。缺失字体时停止自动构建并列出：字体名、涉及页面/对象、影响和候选处理。

只有用户确认后才可：

- 选择替代字体；
- 使用 SVG/图片艺术字替代；
- 保留原字体名并接受本机预览差异。

场景 2–5 的普通正文不得自动替换成图片。场景 1 有意把整页成稿封装为图片，所有文字必须在图片生成时校对准确，并明确不可编辑。标题艺术字若转资产，必须披露编辑边界。
