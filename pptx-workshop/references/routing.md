# 路由规则

根据用户目标选择场景，不按输入文件扩展名机械选择。

| 场景 | 内部值 | 选择条件 |
|---|---|---|
| 从 0 制作 | `new-deck` | 根据主题、资料或数据重新策划并设计一套图片成稿 |
| 原生模板填充 | `template-fill` | 以现有 PPTX 的 Theme/Master/Layout/视觉框架承载新内容 |
| 图片/PDF 重建 | `reconstruction` | 保持源页内容、顺序和布局，追求视觉相似的真实 PPTX |
| 参考稿制作新稿 | `reference-deck` | 参考稿定义风格，但内容和页面故事需要重新策划 |
| 已有 PPT 续写/修改 | `existing-deck` | 在现有 PPTX 中修改指定内容或增加页面，并保持前后口径 |

## 歧义

- “参考这个 PPT 做一套新的”选择 `reference-deck`；“把新内容填进这个 PPT”选择 `template-fill`。
- “把这份 PDF 变成 PPT”若要求原页复刻，选择 `reconstruction`；若只把 PDF 当资料重新讲述，选择 `new-deck`。
- “从 0 做一套并且最终要可编辑”先选择 `new-deck` 完成策划、逐页 PNG 和图片型 PPTX；图片成稿经用户确认后，再以确认过的 PNG 新建一次 `reconstruction`。不得为了省步骤把两个场景写进同一次运行。
- “接着这份 PPT 再写几页”选择 `existing-deck`，即使新增页很多也不改为 `reference-deck`。
- 多份参考视觉冲突时先让用户指定主参考，禁止自动平均。

## 路由前记录

记录源文件、输出目的、受众、使用场合、页面范围、目标画布、是否锁定页数/顺序/原文、模板保留范围、可修改对象范围和资产政策。源文件只读，输出必须是新路径。
